Presenter cue

Start with the human workflow. This came up in both presentations: people understand the technical findings faster once they can picture the caseworker and client sitting together.

Human situation

A caseworker has minutes to help someone find the right resource.

A client may need food today, transportation help, shelter, legal aid, employment support, or a program that accepts them right now. The caseworker needs local referrals they can trust during a live conversation.

A wrong phone number is not a small error when someone is already trying to get help.

Fast enough to use

When a tool takes more than a minute in a live session, caseworkers fall back to memory.

Accurate enough to share

The highest-impact quality issues were relevance, completeness, and contact information.

Readable enough to act on

Recommendations had to be simple enough for caseworkers to share directly with clients.

Track 1: PM parameter toolkit

The fastest way to improve an AI product may be changing the knobs you already control.

The key is to evaluate each knob against the same user-centered rubric. Don’t just ask which model is fastest; ask which configuration is fast enough, reliable enough, and good enough for the actual workflow.

Deterministic checks

Fast structural coverage

JSON validity, count limits, URL checks, readability formulas, duplicates, contact completeness, grounding, and location.

LLM judges

Scalable qualitative review

Specialized rubric prompts reviewed low-scoring traces and explained why an answer failed.

Human calibration

Define the standard

Case managers and reviewers shaped the rubric, calibrated the evals, and caught things automation missed.

Source verification

Check the real world

For high-risk samples, humans checked organization websites and authoritative databases to verify contact details.

Cross-track finding

Web search was essential, but more search was not always better.

What the delivery-team presentation added

Show the evaluation harness as a path teams can copy, not only a finished system.

The AI forward delivery team was interested in how to build an experiment and evaluation harness from manual workflows. The presentation should make the build path explicit.

Layer 1

Observe

Get product trace visibility: users, speed, query types, outputs, RAG context, and web search behavior.

Layer 2

Batch grade

Create a rubric and score traces at scale with a mix of deterministic checks and specialized judges.

Layer 3

Deep review

Use expert-informed qualitative review for low-scoring or high-risk samples.

Layer 4

Experiment

Test models, prompts, reasoning, temperature, and search behavior against a fixed corpus.

Layer 5

Automate

Propose prompt changes, compare results, and deploy only when improvements pass regression checks.

Implementation framing: individual tools were built in days to a week, while the overall evaluation process took roughly two months because it evolved through manual, coding, and agentic approaches.
For expert-heavy domains

Use experts to define and calibrate quality, not to review everything forever.

The delivery-team conversation raised a key issue for legal and policy tools: teams may not have legal or subject-matter expertise internally, and client experts do not have unlimited time.

Ask SMEs for criteria

What makes an answer useful, risky, incomplete, or wrong?

Calibrate with samples

Have experts review representative outputs and explain scoring decisions.

Encode the rubric

Turn expert judgment into deterministic checks, judge prompts, and allowed values.

Reserve expert review

Send edge cases, low-confidence outputs, and regression failures back to humans.
